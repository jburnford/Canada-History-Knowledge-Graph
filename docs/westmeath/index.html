Workshop Context

This page demonstrates how to convert flat Historical GIS (HGIS) data into a CIDOC-CRM knowledge graph, using Westmeath Township as a worked example. The source data is the Canadian Historical GIS (CHGIS), which provides census subdivision polygons and tabular census returns for 1851–1921.

The conversion is not just a format change. It requires resolving fundamental modelling challenges: persistent identity for places that change identifiers each decade, temporal scoping of measurements and administrative hierarchies, and provenance tracking back to the original source tables.

HGIS Source Data

The Canadian Historical GIS (CHGIS / TCP) provides two types of data: polygon boundaries in a FileGDB, and census returns in Excel spreadsheets. Both are keyed by a per-year polygon identifier (TCP UID).

CIDOC-CRM Knowledge Graph

The CIDOC-CRM (Conceptual Reference Model) is an ISO standard ontology for cultural heritage. It provides a formal vocabulary for describing objects, events, places, people, and their relationships over time. Our implementation uses CIDOC-CRM classes to model both the spatial structure (places, presences, coordinates) and census observations (measurements, dimensions, units).

HGIS ↔ Knowledge Graph Comparison

HGIS Flat Model

Data Structure

  • Spatial: FileGDB with one polygon layer per census year
  • Tabular: Excel spreadsheets with one row per CSD per year
  • Identity: TCP UID per census year (not persistent)
  • Linking: Computed post-hoc via spatial overlap (IOU)
  • Names: Stored as-is in attribute fields (OCR errors included)
  • Hierarchy: CSD → CD encoded in UID prefix + attribute
  • Provenance: Filename convention (year_volume_table)
CIDOC-CRM Knowledge Graph

Data Structure

  • Spatial: E53_Place (persistent) + E93_Presence (per year) + E94_Space_Primitive (centroid)
  • Tabular: E16_Measurement → E54_Dimension → E58_Unit
  • Identity: Persistent place ID from Union-Find over SAME_AS chains
  • Linking: P132_spatiotemporally_overlaps + PLACE_LINEAGE
  • Names: E41_Appellation (canonical on place, variants on presence)
  • Hierarchy: P89_falls_within with temporal scope
  • Provenance: E73_Information_Object → P70_documents → E16 + E42_Identifier (TCP UID)

What the Conversion Gains

  • Persistent identity: “Show me everything about Westmeath” is one query, not 7 table joins
  • Semantic typing: Every measurement has a formal type (E55), unit (E58), and provenance (E73) — not just a column header
  • Temporal reasoning: Administrative changes (CD splits/merges) are first-class relationships, not implicit in changing attribute values
  • Data quality: OCR errors become explicit variant names, not silent data corruption
  • Cross-dataset linking: Standard ontology classes (E53, E93, E16) can link to other CIDOC-CRM datasets
  • Full provenance chain: Any measurement traces back to its source file (DOI), presence (TCP UID), and variable definition

What the Conversion Loses

  • Full polygon geometry: Only centroids are stored; boundary analysis requires returning to the FileGDB
  • Simplicity: A flat spreadsheet cell becomes a 6-node path (E73 → E16 → E54 → E58 + E93 + E55)
  • GIS tool support: Standard GIS tools cannot directly consume the knowledge graph
  • Storage efficiency: 666,423 measurements generate ~4M nodes and relationships (vs ∼500 MB of CSVs)

Sample Neo4j (Cypher) Queries

These queries demonstrate how the CIDOC-CRM model enables temporal, thematic, and provenance queries that would require complex joins in the flat HGIS model.

All census data for a place, all years

// Every measurement for Westmeath across all census years
MATCH (place:E53_Place {name: 'Westmeath', province: 'ON'})
  <-[:P166_was_a_presence_of]-(p:E93_Presence)
  -[:P164_is_temporally_specified_by]->(period:E4_Period)
OPTIONAL MATCH (p)<-[:P39_measured]-(m:E16_Measurement)
  -[:P2_has_type]->(vtype:E55_Type)
  -[:P40_observed_dimension]->(d:E54_Dimension)
  -[:P91_has_unit]->(u:E58_Measurement_Unit)
RETURN period.year, vtype.category, vtype.label, d.value, u.label
ORDER BY period.year, vtype.category, vtype.label

Returns 454 rows: all population, agriculture, manufacturing, ethnicity, mortality, building, and fisheries data.

Agricultural production over time

// Track oat and potato production in Westmeath across decades
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  <-[:P166_was_a_presence_of]-(p:E93_Presence)
  <-[:P39_measured]-(m:E16_Measurement)
  -[:P2_has_type]->(vtype:E55_Type)
  -[:P40_observed_dimension]->(d:E54_Dimension)
WHERE vtype.variable_name IN ['OAT_XX_B', 'POT_XX_B']
RETURN p.census_year AS year, vtype.label, d.value
ORDER BY year, vtype.label

Full provenance chain

// Trace a measurement back to its source file and original TCP UID
MATCH (m:E16_Measurement {measurement_id: 'MEAS_ON082003_1871_POP_XX_N'})
  -[:P39_measured]->(p:E93_Presence)
  -[:P1_is_identified_by]->(tcpuid:E42_Identifier)
MATCH (m)-[:P2_has_type]->(vtype:E55_Type)
MATCH (m)-[:P40_observed_dimension]->(d:E54_Dimension)
  -[:P91_has_unit]->(u:E58_Measurement_Unit)
MATCH (source:E73_Information_Object)-[:P70_documents]->(m)
RETURN source.label AS source_file,
       tcpuid.value AS original_tcp_uid,
       vtype.label AS variable,
       d.value AS value, u.label AS unit

Returns: source=1871_V1T1_CSD_202306.xlsx, tcp_uid=ON082003, variable=Total population, value=2632, unit=persons

Compare two places across categories

// Compare Westmeath and a neighbour (Ross) in 1891
MATCH (place:E53_Place)-[:P122_borders_with]-(neighbour:E53_Place)
WHERE place.place_id = 'PLACE_ON142032'
  AND neighbour.name = 'Ross'
WITH place, neighbour
UNWIND [place, neighbour] AS p
MATCH (p)<-[:P166_was_a_presence_of]-(pres:E93_Presence {census_year: 1891})
  <-[:P39_measured]-(m:E16_Measurement)
  -[:P2_has_type]->(vtype:E55_Type)
  -[:P40_observed_dimension]->(d:E54_Dimension)
WHERE vtype.variable_name IN ['POP_XX_N', 'HOUSE_XX_N', 'OAT_XX_B']
RETURN p.name, vtype.label, d.value
ORDER BY p.name, vtype.label

Find all places by category coverage

// Which places have manufacturing data in 1851?
MATCH (m:E16_Measurement)-[:P2_has_type]->(vtype:E55_Type {category: 'MFG'})
  -[:P39_measured]->(p:E93_Presence {census_year: 1851})
  -[:P166_was_a_presence_of]->(place:E53_Place)
WITH place, count(m) AS mfg_vars
RETURN place.name, place.province, mfg_vars
ORDER BY mfg_vars DESC LIMIT 20

Administrative hierarchy over time

// Westmeath's changing census division assignment
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  -[r:P89_falls_within]->(cd:E53_Place {place_type: 'CD'})
RETURN cd.name AS census_division, r.during_period
ORDER BY r.during_period
