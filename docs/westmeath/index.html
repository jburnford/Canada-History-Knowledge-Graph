Westmeath at a Glance

Westmeath is a township in Renfrew County, Ontario, on the Ottawa River. Its boundaries remained stable across all eight census years (1851–1921), making it an ideal test case for comparing how different data models handle temporal identity.

CIDOC-CRM Model (Current Implementation)

The CIDOC-CRM model uses E53_Place (persistent), E93_Presence (temporal), E94_Space_Primitive (coordinates), and E4_Period (census year) to separate place identity from temporal manifestation.

Entities Created for Westmeath

Problem: Because the TCP UID changes each year, the current implementation creates a separate E53_Place for each ID. Westmeath appears as multiple "places" rather than one place with multiple presences.

Model Comparison

HGIS

How HGIS Represents Westmeath

  • Identity: TCP UID per census year (7 different IDs)
  • Continuity: Spatial overlap links between consecutive years
  • Name: Stored per-year in the census tables
  • Geography: Full polygon boundary per year
  • Hierarchy: CSD → CD → Province, per year
  • Data: Census variables attached directly to polygon ID + year

Strengths

  • Simple, flat structure
  • Each year is self-contained
  • No ambiguity about what polygon a measurement refers to

Weaknesses

  • No persistent identity — "Westmeath" is 7 different entities
  • Cross-year queries require following link chains
  • Same ID reused for different places in different years
CIDOC-CRM

How CIDOC-CRM Should Represent Westmeath

  • Identity: One E53_Place with a persistent URI
  • Continuity: Multiple E93_Presence nodes linked to the same E53_Place
  • Name: E41_Appellation(s) with temporal validity
  • Geography: E94_Space_Primitive per presence
  • Hierarchy: E53_Place → E53_Place (CD) via P89
  • Data: E16_Measurement → E93_Presence

Current Implementation Gap

  • E53_Place created per TCP UID, not per real-world place
  • ON082003 is treated as one place but used for Westmeath (1871), Burgess (1861), Plympton (1891)
  • ON114011 is "Osprey" (its 1921 canonical name) but represents Westmeath in 1881/1891
  • No single node you can query for "all Westmeath data"

Modeling Issues Exposed by Westmeath

Issue 1: ID Reuse Across Years
TCP UID ON082003 represents different physical places in different census years:
  • 1861: Burgess (Lanark County, 44.79°N 76.28°W)
  • 1871: Westmeath (Renfrew North, 45.76°N 76.88°W)
  • 1891: Plympton (Lambton West, 43.01°N 82.11°W)
  • 1901: Kemptville Village (Leeds & Grenville, 45.02°N 75.65°W)
  • 1911: Stanley (Huron S, 43.51°N 81.61°W)

Creating a single E53_Place for ON082003 conflates 5 completely different townships.

Issue 2: Canonical Name Mismatch
The E53_Place canonical name is set from the CSD's latest census year appearance, not the year it represents Westmeath:
  • ON114011 → named "Osprey" (from 1921), but is Westmeath in 1881/1891
  • ON110012 → named "Sandwich S" (from 1921), but is Westmeath in 1901
  • ON116010 → named "Hayelock" (from 1921), but is Westmeath in 1911
Issue 3: OCR Error Preserved
In the 1881 census data, Westmeath is spelled "Wesmeath" (missing 't'). The year_links caught this (name_similarity: 95.88) but the HGIS data preserves the OCR error. The canonical name correction system identified it but the chain is incomplete (only 2 years tracked in chain_00313).
Issue 4: Census Division Name Variation
Renfrew County appears as: "Renfrew" (1851, 1861, 1921), "Renfrew, North—Nord" (1871–1901), "Renfrew N" (1911). These are the same administrative area but inconsistently named across census years — a parallel identity problem at the CD level.

Proposed Solution

  1. Create persistent E53_Place entities by following SAME_AS chains, not by TCP UID. Each chain of SAME_AS links with IOU=1.0 = one persistent place.
  2. Keep E93_Presence per census year linked to the single E53_Place via P166. The presence retains the original TCP UID as a provenance property.
  3. Handle CONTAINS/WITHIN chains as place evolution: the persistent place's boundary changed, and the presences before/after the change show different geometries.
  4. Assign canonical names from the most common name in the chain, not from a single year's usage.
  5. Link E41_Appellations temporally — "Wesmeath" is valid for 1881 only (OCR), "Westmeath" is the canonical form.
