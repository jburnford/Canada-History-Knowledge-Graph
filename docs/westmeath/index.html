Westmeath as a Case Study

Westmeath is a township in Renfrew County, Ontario, on the Ottawa River. Its boundaries remained stable across all eight census years (1851–1921), making it an ideal case study for comparing how the two data models represent place identity over time.

The HGIS model treats each census year as an independent layer of polygons, linked by spatial overlap analysis. The CIDOC-CRM model separates the enduring place from its time-specific manifestations, using ontological classes from the cultural heritage domain.

HGIS Source Data

The Historical GIS data from the TCP (Territorial Change Project) assigns each census subdivision a unique polygon ID per census year. Temporal links between years are computed by spatial overlap analysis.

CIDOC-CRM Model

The CIDOC-CRM ontology separates the enduring place (E53_Place) from its time-specific manifestations (E93_Presence), with each presence linked to a spatial primitive (E94_Space_Primitive) and census period (E4_Period). Census measurements attach to presences, not places, so they are always grounded in a specific time and geography.

How CIDOC-CRM Represents Westmeath

CIDOC-CRM

Westmeath is a single E53_Place with 8 E93_Presence nodes, one per census year. Each presence keeps its original TCP UID as an E42_Identifier for provenance back to the source GIS data. The persistent place identity is built by Union-Find over SAME_AS chains (IOU = 1.0).

Model Comparison

HGIS / GIS Flat Model

Representation

  • Identity: TCP UID per census year (7 different IDs for Westmeath)
  • Continuity: Spatial overlap links between consecutive year-layers
  • Name: Stored per polygon in the census tables
  • Geography: Full polygon boundary per year
  • Hierarchy: CSD → CD → Province, per year
  • Data: Census variables join on polygon ID + year

Strengths

  • Simple, flat structure — easy to work with in standard GIS tools
  • Each year is self-contained
  • No ambiguity about what polygon a measurement refers to
  • Full polygon geometry preserved (not just centroids)

Limitations

  • No persistent identity — Westmeath is 7 different entities
  • Cross-year queries require walking link chains
  • Same UID reused for different places in different years
  • No standard vocabulary for relationship types
CIDOC-CRM

Representation

  • Identity: One E53_Place per real-world place (PLACE_ON142032)
  • Continuity: Multiple E93_Presences linked to one E53_Place via P166
  • Name: E41_Appellation with temporal validity
  • Geography: E94_Space_Primitive (centroid per presence)
  • Hierarchy: E53 → E53 via P89, time-scoped
  • Data: E16_Measurement → E93_Presence via P39

Strengths

  • Persistent identity — one node for “Westmeath” across 70 years
  • Clean separation of place, time, space, and measurement
  • OCR variants and canonical names modeled explicitly
  • Full provenance (E42_Identifier retains original TCP UIDs)
  • Interoperable with cultural heritage standards (CIDOC-CRM 7.x)
  • Split/merge history via lineage relationships

Limitations

  • More complex to query (multiple hops)
  • Centroids only, not full polygon boundaries
  • Requires Union-Find pre-processing step
  • Higher node/relationship count

Side-by-Side: Querying Westmeath’s Population History

HGIS 
-- Must know the chain of IDs:
SELECT year, population
FROM census_data
WHERE polygon_id IN (
  'ON033008', 'ON096020', 'ON082003',
  'ON114011', 'ON110012', 'ON116010',
  'ON142032'
)
ORDER BY year;
-- Requires pre-computing the identity chain
-- from year_links spatial analysis
CIDOC-CRM (Cypher) 
MATCH (place:E53_Place
        {place_id: 'PLACE_ON142032'})
  <-[:P166_was_a_presence_of]-
  (p:E93_Presence)
  -[:P164_is_temporally_specified_by]->
  (period:E4_Period)
OPTIONAL MATCH (p)<-[:P39_measured]-
  (m:E16_Measurement)-[:P40]->(d:E54)
WHERE m.label CONTAINS 'POP_XX_N'
RETURN period.year, d.value AS pop
ORDER BY period.year

Sample CIDOC-CRM Queries

All census data for a place

// Every measurement for Westmeath, all years
MATCH (place:E53_Place {name: 'Westmeath', province: 'ON'})
  <-[:P166_was_a_presence_of]-(p:E93_Presence)
  -[:P164_is_temporally_specified_by]->(period:E4_Period)
OPTIONAL MATCH (p)<-[:P39_measured]-(m:E16_Measurement)
  -[:P40_observed_dimension]->(d:E54_Dimension)
  -[:P91_has_unit]->(u:E58_Measurement_Unit)
RETURN period.year, m.label, d.value, u.label
ORDER BY period.year, m.label

Trace provenance back to source GIS

// Which TCP UID did Westmeath have in each census year?
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  <-[:P166_was_a_presence_of]-(p:E93_Presence)
  -[:P1_is_identified_by]->(id:E42_Identifier {identifier_type: 'TCP_UID'})
RETURN p.census_year AS year, id.value AS tcp_uid
ORDER BY year

Administrative hierarchy over time

// Which census division was Westmeath in during each period?
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  -[r:P89_falls_within]->(cd:E53_Place {place_type: 'CD'})
RETURN cd.name AS census_division, r.during_period
ORDER BY r.during_period

Find neighbours

// Westmeath's neighbours in 1871 with shared border lengths
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  -[b:P122_borders_with {during_period: 'CENSUS_1871'}]-
  (neighbour:E53_Place)
RETURN neighbour.name, b.shared_border_length_m
ORDER BY b.shared_border_length_m DESC

Places that split or merged

// What places split from or merged into Westmeath's neighbours?
MATCH (place:E53_Place {place_id: 'PLACE_ON142032'})
  -[:P122_borders_with]-(neighbour:E53_Place)
  -[lin:PLACE_LINEAGE]-(related:E53_Place)
RETURN neighbour.name, lin.lineage_type, related.name, lin.change_year
ORDER BY lin.change_year

OCR corrections

// Find all places with OCR name variants
MATCH (place:E53_Place)-[:P1_is_identified_by]->
      (canonical:E41_Appellation {type: 'canonical'})
MATCH (presence:E93_Presence)-[:P166_was_a_presence_of]->(place)
MATCH (presence)-[:P1_is_identified_by]->
      (variant:E41_Appellation {type: 'variant'})
RETURN place.name AS canonical, variant.name AS ocr_error,
       presence.census_year AS year
ORDER BY place.name
