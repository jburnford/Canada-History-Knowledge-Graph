### ✅ C4 — Census observations rebuild

The existing `neo4j_census_v2/` output stopped at 1901 and had no SK/AB data (those provinces joined Confederation in 1905). Rebuilt across all 8 years against the full census table set.

**Three non-trivial script fixes in `build_census_observations_v2.py`**:

1. **Header detection**. The old logic fell through to `skiprows=3` whenever `TCPUID_CSD_{year}` was absent. 1911 and 1921 tables put the real header on row 0 but use `{source_name}_{year}` as the ID column — the fallback was breaking them. Now any recognised ID column stops the fallback.

2. **Skip CD/country aggregate rows**. Census tables have three hierarchy levels per file (country, CD, CSD). Emitting measurements for every row inflated naive province sums by exactly 3×. Now filtered on `CD_NO == 0 || CSD_NO == 0`, handling non-numeric values like `"20N"` as valid CSDs. 4,393 aggregate rows skipped.

3. **Deduplicate `(tcpuid, year, var)` measurements**. Multiple source tables report the same variable (e.g., `POP_TOT_1921` appears in 3 different 1921 tables). The old script emitted duplicate `measurement_id:ID` rows that Neo4j's `LOAD CSV` would reject. Now we emit one canonical E16/E54 per key and append extra `P70_documents` edges for each additional source. **50,387 duplicate combos collapsed; 0 duplicate IDs remain.**

Also: **output now sharded per year** to stay under GitHub's 100MB file limit. Largest shard ~10MB (down from a pre-split `e16_measurements_all.csv` at 122MB and `p40_observed_dimension_all.csv` at 126MB).

## Known follow-ups (not blocking workshop demo)

1. **P132 edge properties still present**. `p132_spatiotemporally_overlaps_with_csd.csv` and `_cd.csv` carry `overlap_type`, `iou`, `from_fraction`, `to_fraction`, `year_from`, `year_to` as edge properties. Unlike the other relationships, these are real continuity-analysis data that can't just be dropped — they need a proper reification (likely `E13_Attribute_Assignment` or another E16 pattern). **Deserves its own workshop discussion** because the reification shape isn't obvious.

2. **Year "1860" parsing quirk**. 2,058 rows in the census observations are dated `1860` instead of `1861` due to a column-name regex matching on column headers like `POP_1860` in 1861 tables. Cosmetic but worth a fix.

3. **Two E58 measurement-unit files**. `neo4j_cidoc_crm_v2/e58_measurement_unit.csv` (1 row: metre, from C3) and `neo4j_census_v2/e58_measurement_units.csv` (11 rows: persons, acres, dollars, etc.) are separate. Neither imports the other. The RDF exporter can dedupe at serialisation time — no upstream fix needed. If we want one canonical file it's a 10-minute merge.

4. **Border measurement typing**. My C3 E16 nodes carry a `measurement_type = 'shared_border_length'` column as a literal. LINCS-idiomatic form would use `P2_has_type → E55_Type` (which the census observations already do for their variables). Minor inconsistency; fix when we standardise the typing approach for all E16s.

5. **`neo4j_census_v2.bak/`** left on disk from the C4 rebuild. Delete manually when you're confident in the new output.

6. **11 unplaced grounding records** (`neo4j_cidoc_crm_v2/e53_place_uri_unplaced.csv`). Each is a CSD the disambig tool verified but that has no 1921-active row in the E53 CSV. Likely further fallout from the upstream year-scoped-tcpuid issue. Worth investigating individually if any are high-profile (Brampton and Shediac are in the list).

7. **Grounding for the rest of Canada** is tracked in the other session. Currently ON, SK, QC, NB, MB, BC, NS, PE, AB are complete to varying degrees; ~1,975 CSDs across the remaining provinces are still unverified. The RDF exporter's URI sidecar pattern is grounding-incremental — it picks up whatever is current in `csd_verified_matches.jsonl` at build time, so the rest-of-country pass can land any time without re-running C1.
